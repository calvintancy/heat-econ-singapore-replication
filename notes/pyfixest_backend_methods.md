# Native PyFixest estimation backend

Implemented 11 November 2026 in `scripts/pyfixest_backend.py`, using installed PyFixest **0.70.0**. The project dependency and lock record the software version. This is an estimator migration on fixed designs and samples, not a new outcome transformation or a change in inference convention.

## Actual estimator and explicit fixed effects

Every backend fit calls native `pyfixest.feols`. Native `Feols.coef()` supplies all estimated coefficients, including fixed-effect nuisance coefficients. Native `Feols.resid()` supplies all stored residuals. No statsmodels or independent NumPy coefficient fit is used by the production adapter.

Formula calls use Patsy solely to construct the same explicit full-rank design used previously. Matrix calls receive the caller's complete design. Fixed effects are represented by explicit indicator columns—ordinary least-squares dummy-variable estimation—rather than PyFixest's absorption interface. This is a genuine native PyFixest FE regression with an explicit basis. It preserves the precise nuisance basis, coefficient names, row order and full parameter count needed by the existing audited covariance calculations.

For numerical stability, let `D` contain the original columns' Euclidean norms and compute the **design-only** decomposition `X D⁻¹ = U S V′`. Native PyFixest estimates `Y = U θ + ε` using every orthonormal U column, temporarily called `x0000`, `x0001`, etc. Its formula is `y ~ 0 + x0000 + x0001 + ...`; no intercept or extra regressor is added. The original design's complete intercept/FE basis is preserved in this invertible coordinate system. Original coefficients are recovered as `β = D⁻¹ V S⁻¹ θ_native`. The adapter never computes `U′Y` or a second coefficient fit. This is a reparameterisation of the same full LSDV model, not an alternative regression or a change to the original outcome.

The actual native coordinates differ from the logical, named weather/FE columns. The receipt explicitly records that distinction through the native-basis label, native design hash, original column names/scales, and coefficient-transform hash/dimensions. The wrapper retains the transform and native coefficients alongside its actual Feols model. The original-X sandwich bread is `B B′` for `B = D⁻¹ V S⁻¹`.

The caller can therefore estimate temperature plus nonreference industry interactions and recover each industry's total response as the baseline temperature coefficient plus its interaction. The custom interaction engines own that linear contrast and its covariance; the backend estimates the requested complete matrix without substituting a separate estimator.

## API and safeguards

- `fit(df, formula, label)` returns a compatibility result whose `params` is a named pandas Series and whose formula residuals retain the original row index.
- `fit_matrix(y, X, coef_names, label)` returns one result with NumPy residual arrays.
- `fit_many_matrix(Y, X, coef_names, label, outcome_names=None)` uses native multiple-outcome estimation and returns one native-backed result per input Y column, in that order.
- `reset_fit_log()` starts a fresh production provenance run; `write_fit_log()` writes the completed model-stage inventory.

Every result retains the actual native Feols object as both `native_model` and `pyfixest_model`. The compatibility facade exposes original-X arrays, parameter names, native residuals, sample count and residual degrees of freedom. Conventional R² is computed from native residuals and original Y: it is centered when a constant lies in the design span, including a complete sector-season/date indicator basis. This avoids confusing `0 +` formula syntax with the absence of an implicit constant.

The backend rejects non-finite inputs, a rank-deficient design, nonpositive residual degrees of freedom, duplicate names, any dropped coefficient or row, changed coefficient order, or a native response that differs from its requested Y column. Multi-outcome response identity is checked exactly against `within_data.response`. The native residual identity against the original X and back-transformed coefficients is also checked, without replacing the residuals.

The solver is explicitly pinned to PyFixest's `np.linalg.lstsq` option with collinearity tolerance `1e-12`. Inspection of installed `estimation/internals/solvers.py` confirms that this is a **native normal-equation solve**, not a direct SVD of the original X. The option's name must not be described otherwise. An initial column-scaling-only implementation showed small rounding differences that exceeded precise legacy guards. Passing orthonormal U makes the native normal matrix approximately the identity and addresses that conditioning problem without relaxing those guards. The separate SVD is design-only geometry for preconditioning, rank/constant-span checks and sandwich bread; it never multiplies an outcome to estimate a coefficient. The maximum `U′U−I` error is checked and logged. Native PF estimation and the main geometry use a one-thread BLAS limit. No GPU/cupy backend or absorbed-regressor fallback is used.

## Covariance remains explicit

Native `vcov="iid"` is requested to construct each Feols model. The reported uncertainty is still the project's separately audited sector-CR1 or calendar-HAC sandwich calculation, using the full original X, native PF residuals and the original parameter count. The adapter back-transforms the design bread to original units. Native iid SEs are not silently relabelled as the reported robust SEs.

This separation preserves the existing handling of actual calendar gaps, Bartlett bandwidths, cross-sector covariance and finite-sample factors. Common slopes retain sector-CR1 where specified. Individual-sector, national-total and sector-specific interaction slopes retain their stated time/joint calendar HAC exceptions. The estimator migration does not resolve small-sample, stationarity or causal-identification limitations.

## Durable provenance and validation scope

`outputs/pyfixest/fit_log.csv` contains one row per actual native Feols model, including each outcome in a native multiple-outcome call. It records sequence/API IDs, labels, outcomes, version, native class/module, actual formula, N/K, solver, logical/scaled/native design hashes, the orthonormal basis label/error, coefficient-transform hash/dimensions/rank, Y and native-Y hashes, coefficient-name/scale hashes, native/back-transformed coefficient hashes, native/residual hashes, exact response/design/mapping errors, residual identity error and any dropped rows/columns. `estimator_manifest.json` records the run, implementation and receipt hash. Reset marks the new run as running so a stale completed inventory is not reused. Writing the inventory is not itself a claim that independent migration validation passed.

Final orthonormal-native prototypes compared the VA baseline, full-control C4, raw-level H1 and a large relative-effects design with independent direct-X OLS. The 2,430×645 three-outcome relative-effects design retained exact Y ordering and matched coefficients within 1.3×10⁻¹¹ and residuals within 1.5×10⁻¹¹. Baseline/C4 all-coefficient differences were at most 2.35×10⁻¹¹/7.04×10⁻¹¹; their FWL identities differed by 2.17×10⁻¹³/1.96×10⁻¹². C4's maximum all-parameter HAC-SE difference was below 4.12×10⁻⁹. The deliberately raw-temperature raw-level H1 formula had an absolute nuisance-coefficient difference up to 1.40×10⁻⁷, residual difference below 4.62×10⁻⁹ and maximum all-parameter HAC-SE difference below 3.29×10⁻⁶ in its original currency units. Its R² differed by only 2.3×10⁻¹⁵. Scale-aware verification still matters for large nuisance coefficients and their uncertainty; none of these comparisons is described as bit-identical.

The temporary receipt test checks actual Feols objects, exact multi-outcome response and residual hashes, zero mapping errors, and correct one-call/two-model counts. Full production validation against the frozen pre-migration outputs and independent linear-algebra verifiers is a separate pipeline stage; its current durable receipt is the authority for the all-model completion claim. The initial migration inventory contained 1,194 native models. The expanded main source analysis contains 1,510 after adding NSA YoY companions, including the retained partial-regression fits and separate-series equations. Annual and paired-COVID analyses have isolated receipts. Current expected counts are reconstructed from the model/outcome/unit inventories and checked after estimation; the sealed fit logs and verification receipts govern current completion claims.
